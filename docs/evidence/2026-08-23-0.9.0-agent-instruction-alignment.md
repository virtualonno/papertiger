# Papertiger 0.9.0 agent-instruction alignment review

Date: 2026-08-23  
Host: Windows, Europe/Amsterdam

## Verdict

The agent-instruction architecture did not need a wholesale rewrite. Its
always-loaded repository guidance, thin Agent Skills envelope, and complete
vendored operating contract already form the correct progressive-disclosure
boundary. Compressing the operating contract into the envelope would remove
authority, refusal, recovery, provenance, and transfer semantics needed by a
fresh mutating consumer.

The adversarial pass did find four material alignment gaps:

1. The live metaphor `trip-wire` named a real routing concept imprecisely. It is
   now `repository guidance discovery trigger` everywhere current users and
   agents see it. Historical evidence retains the former wording when quoting
   or invalidating an earlier candidate.
2. The trigger named an action but not its exact target or ordering. It now
   requires agents to read `.agents/skills/papertiger/SKILL.md` completely
   before the first edit or commit on qualifying work.
3. Known user provenance and inward commit associations were described as
   optional or only demonstrated in examples. Directly requested durable
   intent now defaults to `--intent-source user`; a commit-backed outcome
   receives its full-OID association before task completion.
4. Human release prose had no dedicated writing contract. The repository now
   includes a validated `changelog-writing` skill and the 0.9.0 changelog has
   been rewritten through it.

The frozen workspace-built release artifact passes all eight retained routing
and exclusion cells. Codex, Claude Fable, Pi Luna, and Pi DeepSeek V4 Flash
route the two qualifying outcomes completely. All four exclusion controls leave
the planning authority unchanged and respect their repository mutation
boundary. Three earlier instruction-alignment matrices still contain two
DeepSeek misses and one incomplete route. Those results remain preserved. One
8/8 artifact run demonstrates release behavior; it does not establish universal
or stable instruction following by an external model.

## Review method

The review applied the invariant-ledger, deletion, blind-execution, conflict,
failure, scope, freshness, and forward-consumer tests from
`F:\AI\wow_modernclient\docs\ai_instruction_optimization.md`. Human-facing
writing criteria were cross-checked against
`F:\AI\linear-skills\skills\linear-writing\SKILL.md` without changing the
Linear-specific skills product.

The source hierarchy was current repository behavior and tests, then exact
Git diffs and public documentation. Existing task results and evidence prose
were treated as navigation until recomputed.

## Invariant ledger

| Class | Preserved operational contract |
| --- | --- |
| Objective | Qualifying durable outcomes enter one project-local tasklog and remain resumable across agents and sessions. |
| Completion | Commit-backed outcomes have known intent provenance, inward full-OID association, truthful result, satisfied dependencies and gates, and a clean audit. |
| Scope | Multi-outcome, separate-commit, exact-resume, dependency, decision, probe, and proof work qualifies; bounded edits, read-only review, intermediate steps, and domain-owned lifecycle skip. |
| Authority | The receipt-selected planner binary and canonical SQLite authority are authoritative; Git and domain systems retain their own facts. |
| Identity | The skill path, binary path, authority path, `task.seq`, meaning-source vocabulary, and full commit object ID are exact. |
| Order | Read skill before edit or commit; read live status before mutation; commit, associate inward, then complete. |
| Failure | Missing or foreign authorities, stale schemas, blocked lifecycle, invalid evidence, and incomplete projections refuse with corrective input or commands. |
| Evidence | `show --json`, bounded projections, audit, commit resolution, retained raw captures, and SHA-256 receipts support claims. |
| Freshness | One clean source checkpoint and one frozen workspace-built binary hash bind the release-artifact statement. Windows relinks are not claimed to reproduce byte-for-byte. |
| Consumer | The thin skill handles discovery; the vendored contract handles mutation and recovery; Mise remains behind its explicit campaign trigger. |

## Deletion and naming judgment

The following edits improved function without deleting operational content:

- `trip-wire` became `discovery trigger` and `Mise Boundary (trip-wires)`
  became `Mise Integrity Boundaries`.
- `Fail-closed is the house style` became `Fail-closed is the project
  standard`.
- A 292-line operating contract is no longer described as `one-page`.
- Setup output, README guidance, the root contract, and the installed contract
  use the same discovery-trigger vocabulary.

The existing compact CLI nouns `status`, `focus`, `candidate`, `trial`,
`projection`, and `authority` were retained because each names a distinct
function. Exact executable and test identifiers were not renamed for prose
novelty.

No material compression was applied to `agent_integration.md`. Its length is a
consequence of mutation, recovery, transfer, evidence, and failure contracts,
not narrative padding. The 3,030-byte skill remains the bounded discovery and
orientation layer.

## Evaluation protocol

Each matrix used eight fresh repositories and authorities:

- four indirect two-outcome routing requests through Codex CLI, Claude Code
  with Claude Fable, Pi with GPT-5.6 Luna, and Pi with DeepSeek V4 Flash;
- one bounded-edit control, one read-only review control, and two domain-owned
  lifecycle controls;
- initial event head 1 and zero tasks in every authority;
- one installed candidate hash across all eight repositories;
- exact prompt, raw stream, final response, event delta, task context,
  commit resolution, worktree status, and audit retained per cell.

Harness identities were Codex CLI `0.148.0` with its configured default model,
Claude Code `2.1.241` with `claude-fable-5`, and Pi `0.84.2` with
`opencode-go/gpt-5.6-luna` or `opencode-go/deepseek-v4-flash`. Codex's retained
stream does not provide an exact model identity, so none is inferred.

The first new matrix exposed a fixture defect: optional Python test execution
created untracked `__pycache__` in otherwise correct bounded and read-only
controls. Later fresh fixtures set `PYTHONDONTWRITEBYTECODE=1` and baseline a
Python cache ignore. This prevents interpreter residue from being mistaken for
tasklog-routing failure. The contaminated first results remain retained.
