# Toolkit and agent integration assessment

This review distinguishes a useful engineering capability from evidence of
recursive self-improvement. It covers the Papertiger and Contextmink source
checkouts and locally built Windows integrations.

## Judgment

| Tool | Justified role | What the evidence does not establish |
| --- | --- | --- |
| Papertiger | Durable intent, obligations, rationale, and resumption across sessions, in one local authority. | That every request needs a task, or that installing a skill guarantees a harness follows it. |
| Contextmink | Bounded generic retrieval with explicit scope and display limits, alongside domain-native tools. | That every read needs a wrapper, that a shallow directory display is a cheap traversal, or that a summary contains the underlying evidence. |
| Mise | Frozen comparative experiments, calibration, budgets, negative evidence, recovery, and rederivation for trusted local engineering. | Net improvement in agent capability, a productive autonomous proposal loop, independent collector truth, or production promotion. |

Mise earns its place as an episodic experiment authority when the comparison
needs those properties. Its existence is not yet justified by a demonstrated
general RSI payoff. A campaign that truthfully rejects a bad candidate is
useful; it is not a successful capability improvement. The decisive future
comparison is useful accepted improvements and total agent/operator cost under
Mise versus ordinary engineering on the same kind of work. Adding an internal
planner or model-provider loop would not supply that missing evidence.

The practical difficulty in this review was obtaining a usable entry path,
recovering candidate identities, and handling output limits without repeated
guesswork. These support concrete changes rather than another orchestration
layer.

## Implementation alignment

The Papertiger skill now contains the ordinary enter, resume, record, and
completion workflow. The full reference is conditional on installation,
recovery, authority changes, and advanced operations. Existing durable work
takes precedence over the bounded-edit/read-only skip. Routine activity does
not require narration or a final tool inventory. The scope remains one task per
independently reviewable outcome, rather than one task per implementation step.

Mise supplies its own version-matched `guide` and `guide --reference` through
the binary. `campaign inspect` discovers candidate roles and nomination IDs,
trial IDs, cohort IDs, and reservation bindings in bounded read-only pages.
Continuation arguments retain the exact project and database. The response
explicitly distinguishes recorded state from CAS verification, process
liveness, and current execution readiness.

Contextmink reports the grep display controls actually exhausted and the
remaining range of a capped line slice. Its skill explains per-file versus
file-count limits, nested JSON selection, optional directory orientation, and
conditional reference loading. It preserves the distinction between inspected
scope, displayed payload, and child exit truth.

## Verification and limits

- Papertiger workspace verification passed 313 tests, with four existing
  explicit ignores. The separate serialized deterministic dogfood passed its
  two selected cases, including the lifecycle's subprocess helper. It exercised
  successful nomination, crash/interruption recovery, successor admission, and
  discovery of real candidate/trial rows. CLI pagination was followed from an
  unrelated working directory against the selected authority.
- Contextmink's source gate passed 420 tests, strict Clippy, format checking,
  package verification, and the declared Rust 1.95 minimum check. The new
  public-CLI tests reconstruct forward and tail windows without gaps or
  duplicates, distinguish character clipping from missing lines, and recover
  grep matches by changing the reported control.
- The selected skill copies and their references were refreshed through public
  setup commands. Repeated setup converged, repository policy was preserved,
  and nested-directory use selected the intended project/profile. Guidance
  mirrors remained byte-identical; skill frontmatter validation passed.
- The ten retained native trial receipts for
  `contextmink-native-behavior-a02` and `ghidramink-native-behavior-a03` were
  reopened with their exact frozen drivers and independently hashed. Their
  research projections rederived unchanged rejection and no nomination. This
  was historical evidence reopening, not fresh execution of the native
  workloads or a new improvement result.
- Both local planner audits reported no findings. All 91 existing Papertiger
  evidence bindings verified. These checks do not validate the domain meaning
  of a collector's observations.

The changed source was checked on Windows. Syntax, packaging, and local workflow
tests do not prove automatic invocation in a fresh harness. This review makes
no claim of a measured increase in unprompted skill adoption or universal
cross-model reliability. Such an evaluation needs independent positive and
negative requests, exact harness/model context, and observation of actual tool
use and durable state, without coaching the evaluator toward the desired route.

## Integration standard

Invisible integration means the agent selects the smallest useful authority,
loads only the necessary contract, receives enough information to recover from
a refusal or cap, and communicates only consequential state. It does not mean
hiding limitations, silently initializing missing history, turning every small
edit into planning work, or allowing experimental evidence to authorize its own
integration.
